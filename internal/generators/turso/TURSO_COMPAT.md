# Turso LibSQL Compatibility Notes

This document outlines SQLite query language features that are **NOT supported** by Turso LibSQL
and must NOT be generated by this SQL generator.

Reference: https://github.com/tursodatabase/turso/blob/main/COMPAT.md#sqlite-query-language

## Unsupported Expressions

The following expression types are NOT supported and should NEVER be generated:

### Subquery Expressions
- `(NOT) IN (subquery)` - **NOT SUPPORTED** (use IN with value list instead)
- `(NOT) EXISTS (subquery)` - **NOT SUPPORTED** (use JOINs or derived tables in FROM instead)

### Binary Operators
- `%` (modulo) - **NOT SUPPORTED**
- `!<` (not less than) - **NOT SUPPORTED**
- `!>` (not greater than) - **NOT SUPPORTED**

### Pattern Matching
- `(NOT) REGEXP` - **NOT SUPPORTED**
- `(NOT) MATCH` - **NOT SUPPORTED**

### Aggregate Features
- `agg() FILTER (WHERE ...)` - **NOT SUPPORTED** (is incorrectly ignored)
- `... OVER (...)` window functions - **NOT SUPPORTED** (is incorrectly ignored)

### Other Expressions
- `RAISE` function - **NOT SUPPORTED**

## Unsupported Scalar Functions

- `format(FORMAT,...)` - **NOT SUPPORTED**
- `load_extension(X,Y)` with 2 parameters - **NOT SUPPORTED**
- Various sqlite3 compile-time options functions - **NOT SUPPORTED**

## Partially Supported Features

### COLLATE
- Only default collations supported: `BINARY`, `NOCASE`, `RTRIM`
- Custom collations are **NOT SUPPORTED**

### Schemas
- `schema.table.column` syntax is **NOT SUPPORTED**
- Use `table.column` instead

### WITH Clause (CTEs)
- `RECURSIVE` keyword - **NOT SUPPORTED**
- `MATERIALIZED` keyword - **NOT SUPPORTED**  
- Only `SELECT` supported in CTEs (no DML)

### Transaction Names
- `BEGIN TRANSACTION name` - **NOT SUPPORTED**
- `COMMIT TRANSACTION name` - **NOT SUPPORTED**
- Use unnamed transactions only

## Supported Alternatives

### Instead of EXISTS/IN with subqueries:
- Use derived tables in FROM clause: `SELECT * FROM (SELECT ...) AS subq`
- Use JOINs with appropriate conditions
- Use correlated conditions in WHERE with scalar subqueries (limited support)

### Instead of FILTER clause:
- Use CASE expressions inside aggregates: `SUM(CASE WHEN cond THEN val ELSE 0 END)`

### Instead of window functions:
- Use self-joins with aggregates
- Use subqueries for ranking/numbering operations

## Testing Guidelines

1. All generated SQL must be validated against Turso LibSQL
2. Tests should explicitly verify that unsupported features are NOT generated
3. When adding new generators, verify against COMPAT.md first
4. Prefer using supported features even if they're more verbose
